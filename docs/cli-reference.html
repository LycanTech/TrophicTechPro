CLI Command Reference

Every command used to build, test, ship, and debug the TrophicTechPro Mission Control platform — with explanations and flag breakdowns.

Git
Version control operations run locally and inside GitHub Actions runners.
Clone repository
Local 
git clone https://github.com/org/trophic-mission-control.git
Downloads the full repository history to your local machine.
Flag / ArgPurpose
<url>HTTPS URL of the remote repository
Create and switch to a new branch
Local 
git checkout -b fix/ensure-prod-db-running
Creates a new branch from the current HEAD and immediately switches to it. Used for every bug-fix branch in this project.
FlagPurpose
-bCreate the branch before switching (shorthand for git branch <name> && git checkout <name>)
Stage specific files
Local 
git add .github/workflows/main.yml prisma/seed.mjs
Stages only the listed files for the next commit. More precise than git add . — avoids accidentally including build artifacts or secrets.
Commit staged changes
Local 
git commit -m "fix(ci): ensure production PostgreSQL is running before migrations"
Records the staged snapshot with a Conventional Commits message. Commit messages follow the type(scope): description format used throughout this project.
FlagPurpose
-mInline commit message (bypasses editor)
Push branch to remote
Local 
git push origin dev
git push --set-upstream origin fix/ensure-prod-db-running
Uploads commits to the remote. --set-upstream (or -u) links the local branch to the remote tracking branch so future pushes need only git push.
FlagPurpose
--set-upstream / -uSet the upstream tracking reference on first push
Resolve merge conflict — keep current version
Local 
git checkout --ours .github/workflows/main.yml
git add .github/workflows/main.yml
git commit -m "fix(ci): resolve merge conflict — keep kubectl exec smoke test"
During a git merge, --ours discards the incoming changes and keeps the HEAD version entirely. Used to keep the kubectl-exec smoke test when merging main's retry-loop version.
FlagPurpose
--oursAccept the current branch's version of the conflicting file
--theirsAccept the incoming branch's version instead
View commit log
Local 
git log --oneline -10
Displays the last 10 commits in a compact one-line format showing SHA and message. Used to verify commits landed correctly after pushing.
FlagPurpose
--onelineAbbreviate each commit to one line (short SHA + message)
-NLimit output to N most recent commits
GitHub CLI
Open PRs, trigger workflows, and inspect CI status from the terminal.
Open a pull request
Local 
gh pr create \
  --base main \
  --head dev \
  --title "fix(ci): production health check via kubectl exec" \
  --body "Replaces curl over nip.io with in-cluster kubectl exec"
Creates a pull request from --head into --base. With branch protection on main, all changes go through PRs — this command was used for PRs #34–#37.
FlagPurpose
--baseTarget branch to merge into
--headSource branch containing the changes
--titlePR title (shown in GitHub UI)
--bodyPR description body text
Trigger a workflow manually
Local 
gh workflow run main.yml --ref main
Dispatches a workflow_dispatch event to re-run the pipeline on a specific branch without pushing new commits. Used to re-test the production deploy after fixing NSG rules.
FlagPurpose
--refBranch or tag to run the workflow on
List recent workflow runs
Local 
gh run list --limit 5
Shows the most recent CI runs with their status (completed/in_progress/queued) and conclusion (success/failure). Quick triage tool after a push.
Watch a workflow run live
Local 
gh run watch 12345678
Streams live log output for a specific run ID. Equivalent to watching the GitHub Actions UI but in the terminal.
Merge a pull request
Local 
gh pr merge 35 --squash --delete-branch
Merges PR #35 using squash strategy (collapses all commits into one on main) and deletes the source branch afterwards. All PRs in this project use squash merges.
FlagPurpose
--squashSquash all commits into a single commit on the base branch
--delete-branchDelete the source branch after merging
--mergeMerge commit (alternative strategy)
--rebaseRebase strategy (alternative)
npm / Node.js
Dependency management, dev server, and build commands.
Install dependencies (CI)
CI 
npm ci
Installs exact versions from package-lock.json, deleting node_modules first. Faster and more deterministic than npm install — used in every GitHub Actions job.
Run unit and integration tests
CI 
npm test -- --coverage --coverageReporters=lcov
Runs the Jest test suite with coverage collection. The lcov reporter produces a coverage/lcov.info file that Codecov uploads for tracking.
FlagPurpose
--coverageCollect and report code coverage
--coverageReporters=lcovOutput coverage in LCOV format for Codecov
Production build
CI 
npm run build
Runs the Next.js build pipeline: TypeScript compilation, route optimisation, static generation. Fails on type errors, blocking the Docker build job.
Run seed script directly
CI 
node prisma/seed.mjs
Executes the ES-module seed file directly with Node.js. Used inside the Kubernetes migration Job after prisma migrate deploy completes. The .mjs extension tells Node to treat the file as an ES module without needing "type":"module" in package.json.
Prisma
Schema migration and client generation for the PostgreSQL database.
Apply pending migrations (production)
CI 
npx prisma migrate deploy
Applies all pending SQL migrations from prisma/migrations/ to the target database. Unlike migrate dev, it never creates new migrations — safe for production use inside Kubernetes Jobs.
Generate Prisma client
CI 
npx prisma generate
Generates TypeScript types and the query-builder client from prisma/schema.prisma. Run during Docker build so the generated client is baked into the image.
Create a new migration (local dev)
Local 
npx prisma migrate dev --name add_deployment_table
Diffs the schema against the local database, generates a new SQL migration file, and applies it. Only used during local development — never in CI.
FlagPurpose
--nameName suffix for the migration file (e.g. 20240101_add_deployment_table.sql)
Inspect database schema
Local 
npx prisma studio
Opens a browser-based GUI at localhost:5555 for browsing and editing database records. Used to verify seed data landed correctly.
Azure Auth
OIDC-based authentication used in CI and interactive login for local operations.
OIDC login (GitHub Actions)
CI 
az login \
  --service-principal \
  --username ${{ secrets.AZURE_CLIENT_ID }} \
  --tenant   ${{ secrets.AZURE_TENANT_ID }} \
  --federated-token $ACTIONS_ID_TOKEN_REQUEST_TOKEN
Authenticates the CI runner to Azure using a GitHub-issued OIDC JWT — no stored passwords or client secrets. Requires the id-token: write permission in the workflow.
FlagPurpose
--service-principalLog in as a service principal, not a user
--federated-tokenOIDC JWT from the GitHub token endpoint
--tenantAzure Active Directory tenant ID
Interactive login (local)
Local 
az login
Opens a browser window for interactive Azure AD authentication. Required before running any az commands locally against the subscription.
Set active subscription
Any 
az account set --subscription ${{ secrets.AZURE_SUBSCRIPTION_ID }}
Pins the CLI to a specific subscription so all subsequent commands target the correct account. Run after every az login in CI.
Log in to Azure Container Registry
CI 
az acr login --name ${{ secrets.ACR_REGISTRY }}
Authenticates Docker to push/pull images from Azure Container Registry using the current Azure CLI credentials. Called before docker build and docker push.
Azure AKS
Cluster access and node pool management for the Kubernetes workloads.
Fetch AKS kubeconfig credentials
CI 
az aks get-credentials \
  --resource-group ${{ secrets.AKS_RESOURCE_GROUP }} \
  --name           ${{ secrets.AKS_CLUSTER }} \
  --overwrite-existing
Merges the AKS cluster's connection details into ~/.kube/config, enabling kubectl and helm to reach the cluster. --overwrite-existing ensures stale credentials from a previous run are replaced.
FlagPurpose
--resource-groupAzure resource group containing the cluster
--nameAKS cluster name
--overwrite-existingReplace cached credentials without prompting
List node pools
Local 
az aks nodepool list \
  --resource-group trophic-prod-rg \
  --cluster-name   trophic-aks \
  --output table
Lists all node pools with their mode (System/User), VM size, and node count. Used to discover the dual-nodepool setup (system + app) that caused the 50% traffic-drop bug.
Show AKS cluster details
CI 
az aks show \
  --resource-group ${{ env.AKS_RESOURCE_GROUP }} \
  --name           ${{ env.AKS_CLUSTER }} \
  --query "powerState.code" \
  --output tsv
Returns the cluster's power state (Running / Stopped). Used in the workflow gate to confirm AKS is healthy before attempting a deployment.
FlagPurpose
--queryJMESPath expression to extract a specific field from the JSON response
--output tsvTab-separated output — clean for shell variable assignment
Azure NSG
Network Security Group rules that gate public HTTP/HTTPS traffic to the AKS nodes.
List NSG rules
Local 
az network nsg rule list \
  --resource-group MC_trophic-prod-rg_trophic-aks_eastus \
  --nsg-name       trophic-prod-nsg-aks-app \
  --output table
Dumps all inbound and outbound rules for an NSG in table format. Used to diagnose why external browsers hit ERR_CONNECTION_TIMED_OUT — the existing rule targeted the LB public IP, which Azure had already DNAT'd away by the time the NSG evaluated traffic.
Add HTTP/HTTPS inbound rule
Local 
az network nsg rule create \
  --resource-group        MC_trophic-prod-rg_trophic-aks_eastus \
  --nsg-name              trophic-prod-nsg-aks-app \
  --name                  allow-http-https-inbound \
  --priority             400 \
  --direction            Inbound \
  --access               Allow \
  --protocol             Tcp \
  --source-address-prefix Internet \
  --destination-address-prefix "*" \
  --destination-port-ranges    80 443 31000-32767
The critical rule that fixed public connectivity. Destination "*" matches any IP — necessary because Azure evaluates NSG rules after DNAT, so the destination is already the node's private IP, not the load balancer's public IP. NodePort range 31000-32767 allows NGINX ingress traffic.
FlagPurpose
--priorityLower number = higher priority (100–4096)
--source-address-prefix InternetAllow traffic from any public IP
--destination-address-prefix *Match any destination IP (post-DNAT node IP)
--destination-port-rangesSpace-separated list of ports or ranges
Add rule to system nodepool NSG
Local 
az network nsg rule create \
  --resource-group             MC_trophic-prod-rg_trophic-aks_eastus \
  --nsg-name                   trophic-prod-nsg-aks-system \
  --name                       AllowHTTPFromInternet \
  --priority                   200 \
  --direction                  Inbound \
  --access                     Allow \
  --protocol                   Tcp \
  --source-address-prefix      Internet \
  --destination-address-prefix "*" \
  --destination-port-ranges    80 443
Without externalTrafficPolicy=Local, the Azure LB distributed traffic to both the system and app nodepools. ~50% of requests hit system nodes whose NSG had a blanket DenyInternetInbound rule. This command (and a matching NodePort rule) unblocked traffic on system nodes as an emergency fix while the permanent externalTrafficPolicy=Local solution was deployed.
Azure PostgreSQL
Flexible Server status checks used as a pre-flight gate before migrations.
Check PostgreSQL server state
CI 
az postgres flexible-server show \
  --resource-group ${{ env.PROD_RG }} \
  --name           ${{ env.PG_SERVER }} \
  --query          "state" \
  --output         tsv
Returns the server state string (Ready / Stopped / Starting). The CI workflow gates on == "Ready" before running Prisma migrations — prevents a cryptic connect ECONNREFUSED from the migration Job.
FlagPurpose
flexible-server showGets details for a Flexible Server instance (not the legacy Single Server)
--query "state"JMESPath extracts just the state field from the JSON blob
--output tsvPlain text — suitable for if [ "$STATE" = "Ready" ] shell logic
Start a stopped PostgreSQL server
CI 
az postgres flexible-server start \
  --resource-group ${{ env.PROD_RG }} \
  --name           ${{ env.PG_SERVER }}
Starts the server if the state check returns anything other than Ready. The CI workflow then polls every 15 seconds (up to 10 minutes) for the state to become Ready before proceeding.
Azure Key Vault
Secret retrieval piped into Kubernetes secrets before each deployment.
Read a secret value
CI 
az keyvault secret show \
  --vault-name trophic-prod-kv \
  --name       DATABASE-URL \
  --query      "value" \
  --output     tsv
Retrieves a secret value from Azure Key Vault. Used in the "Pull KV Secrets" CI step — the output is piped into a kubectl create secret generic command to inject database credentials into the cluster without storing them in the workflow file.
Create Kubernetes secret from KV values
CI 
kubectl create secret generic app-secrets \
  --namespace         $NS \
  --from-literal      DATABASE_URL=$(az keyvault secret show ...) \
  --from-literal      NEXTAUTH_SECRET=$(az keyvault secret show ...) \
  --dry-run=client -o yaml | kubectl apply -f -
Combines Key Vault reads with a Kubernetes secret upsert. The --dry-run=client -o yaml | kubectl apply pattern is idempotent — it creates or updates the secret without throwing an error on re-runs.
FlagPurpose
--from-literalInject a key=value pair directly (not from a file)
--dry-run=clientGenerate the YAML manifest without sending it to the API server
-o yaml | kubectl apply -f -Pipe the generated manifest back into kubectl for an upsert
kubectl — Inspect
Querying cluster state for troubleshooting and deployment verification.
List pods in a namespace
Any 
kubectl get pods -n trophic-prod -o wide
Lists all pods with their status, restart count, and node assignment. The -o wide flag adds IP addresses and the node each pod is scheduled on — useful for verifying which nodepool is serving traffic.
FlagPurpose
-nTarget namespace (default is default)
-o wideExtra columns: node name, pod IP, nominated node
--watch / -wStream updates in real time
Get pod name with label selector
CI 
kubectl get pods -n $NS \
  -l "app.kubernetes.io/name=trophic-mission-control" \
  --field-selector status.phase=Running \
  -o jsonpath='{.items[0].metadata.name}'
Selects pods by Helm label and phase, returning just the first pod's name. Used in CI smoke tests and health checks to dynamically resolve which pod to exec into — avoids hardcoding pod names that change on every deploy.
FlagPurpose
-lLabel selector — filter pods by key=value labels
--field-selectorServer-side filter on fields like status.phase
-o jsonpathExtract a specific field using JSONPath syntax
Describe a resource
Any 
kubectl describe pod trophic-app-7f9d8b-xkqv2 -n trophic-prod
kubectl describe service ingress-nginx-controller -n ingress-nginx
Prints human-readable details including events, conditions, and annotations. For pods, the Events section shows why a pod is stuck (ImagePullBackOff, OOMKilled, etc.). For services, it shows the external IP/LoadBalancer ingress and externalTrafficPolicy setting.
Stream pod logs
Any 
kubectl logs -n trophic-prod \
  -l "app.kubernetes.io/name=trophic-mission-control" \
  --tail 100 -f
Streams the last 100 lines of logs from all pods matching the label selector, then follows new output (-f). Used to inspect Next.js server logs after a health check failure.
FlagPurpose
--tail NShow only the last N lines (avoids flooding terminal on busy pods)
-f / --followKeep streaming new log lines until Ctrl-C
--previousShow logs from the previous (crashed) container instance
Check rollout status
CI 
kubectl rollout status deployment trophic-app \
  -n trophic-prod \
  --timeout 300s
Blocks until the deployment's desired replicas are all Available and Ready, or until the timeout. Exit code 0 = healthy rollout, non-zero = timeout or error. Used as a post-deploy gate in CI.
kubectl — Apply
Declarative resource creation and mutation.
Create namespace if not exists
CI 
kubectl create namespace trophic-prod \
  --dry-run=client -o yaml | kubectl apply -f -
Idempotent namespace creation. kubectl create namespace alone fails if the namespace already exists; the dry-run + apply pattern silently no-ops if it's already present.
Apply a manifest from stdin
CI 
cat <<EOF | kubectl apply -f -
apiVersion: batch/v1
kind: Job
metadata:
  name: prisma-migrate
  namespace: trophic-prod
spec:
  template:
    spec:
      containers:
      - name: migrate
        image: trophictech.azurecr.io/mission-control:latest
        command: ["npx","prisma","migrate","deploy"]
EOF
Pipes a YAML heredoc directly into kubectl apply without writing a temp file. Used to launch the Prisma migration Job dynamically with an image tag substituted at runtime.
Patch a service (live fix)
Local 
kubectl patch service ingress-nginx-controller \
  -n ingress-nginx \
  --type merge \
  -p '{"spec":{"externalTrafficPolicy":"Local"}}'
Live-patches the NGINX ingress service to use externalTrafficPolicy=Local, which tells the Azure cloud controller to only route LB traffic to nodes actually running an ingress pod. Applied as an immediate fix while the Helm chart was updated for permanence.
FlagPurpose
--type mergeMerge-patch strategy — shallow merge of the provided JSON with the existing spec
--type strategicStrategic merge patch — smarter for lists and arrays
--type jsonJSON patch (RFC 6902) — precise path-based mutations
kubectl — Exec
In-cluster command execution for smoke tests and health checks — independent of external networking.
Wait for pod readiness
CI 
kubectl wait pod -n $NS \
  -l "app.kubernetes.io/name=trophic-mission-control" \
  --for condition=Ready \
  --timeout 180s
Blocks until all matched pods report Ready=True, then exits with code 0. Guarantees the pod is accepting connections before the exec health check runs — avoids a race where kubectl exec targets a pod that is starting up.
FlagPurpose
--for condition=ReadyWait for the Ready condition to become True
--timeoutMaximum wait time; exit code 1 if exceeded
In-pod health check (smoke test)
CI 
kubectl exec -n $NS $POD -- \
  curl -sf http://localhost:3000/api/health \
  | grep -q '"status":"ok"'
Runs curl inside the application container and checks the JSON response contains "status":"ok". This approach replaced external curl http://app.68.220.239.81.nip.io/api/health — the external path was failing with exit code 28 (timeout) because NSG rules hadn't propagated yet. The in-pod approach bypasses load balancer, ingress, DNS, and NSG entirely.
Flag / PartPurpose
--Separator between kubectl flags and the command to run in the container
curl -sSilent mode — suppress progress meter
curl -fFail with exit code 22 on HTTP 4xx/5xx responses
grep -qQuiet grep — exit 0 if pattern found, exit 1 if not (no output)
Interactive shell in a pod
Local 
kubectl exec -it -n trophic-prod trophic-app-7f9d-xkqv2 -- sh
Opens an interactive shell session inside the running container for live debugging. Used to manually inspect the filesystem, run database queries, or test network connectivity from inside the cluster network.
FlagPurpose
-iPass stdin through to the container
-tAllocate a pseudo-TTY (needed for interactive shells)
kubectl — Jobs
Managing the Kubernetes Batch Jobs that run Prisma migrations.
Delete and re-create a Job (idempotent)
CI 
kubectl delete job prisma-migrate -n $NS --ignore-not-found
kubectl apply -f migrate-job.yaml
Jobs are immutable once created — you can't re-apply a Job with the same name. Deleting first and re-creating is the standard pattern for repeatable CI steps. --ignore-not-found prevents failure on the first ever run when no prior Job exists.
FlagPurpose
--ignore-not-foundExit 0 even if the resource doesn't exist
Poll Job until complete
CI 
for i in $(seq 1 24); do
  STATUS=$(kubectl get job prisma-migrate -n $NS \
    -o jsonpath='{.status.conditions[?(@.type=="Complete")].status}')
  if [ "$STATUS" = "True" ]; then
    echo "Migration complete"; break
  fi
  sleep 10
done
Polls the Job's Complete condition every 10 seconds for up to 4 minutes. kubectl wait --for=condition=complete exists but can miss failures; the polling loop also checks for Failed conditions and streams pod logs on error.
Stream migration Job logs
CI 
kubectl logs -n $NS -l "job-name=prisma-migrate" --follow
Follows log output from the migration Job's pod using the automatically-applied job-name label. Streams Prisma's output directly to the GitHub Actions run log so migration errors are visible inline.
Helm
Kubernetes package manager used for application deployment, ingress setup, and rollbacks.
Add a Helm chart repository
CI 
helm repo add ingress-nginx https://kubernetes.github.io/ingress-nginx
helm repo update
Registers the NGINX Ingress Controller chart repository and refreshes the local index. Run before every deploy so CI always has access to the latest chart version without maintaining a local cache.
Install / upgrade nginx-ingress
CI 
helm upgrade --install ingress-nginx ingress-nginx/ingress-nginx \
  --namespace   ingress-nginx \
  --create-namespace \
  --set controller.service.externalTrafficPolicy=Local \
  --wait
The idempotent ingress install. --install creates the release if it doesn't exist; otherwise upgrades it. externalTrafficPolicy=Local is the key setting — it restricts the Azure LB backend pool to only nodes running an ingress pod, eliminating the split-traffic NSG bug.
FlagPurpose
--installInstall if the release doesn't exist (makes upgrade idempotent)
--create-namespaceCreate the namespace if it doesn't exist
--set key=valueOverride chart values inline
--waitBlock until all resources are Ready
--atomicRoll back automatically if the upgrade fails (used for app deploys)
Deploy application with Helm
CI 
helm upgrade --install ${{ env.HELM_RELEASE }} ./helm/trophic-app \
  --namespace     ${{ env.PROD_NAMESPACE }} \
  --set           image.tag=${{ env.IMAGE_TAG }} \
  --set           replicaCount=3 \
  --atomic \
  --timeout       10m
Deploys (or upgrades) the application Helm chart with a specific image tag and replica count. --atomic triggers an automatic rollback to the last successful release if the upgrade fails within the timeout window.
Canary deployment (20% traffic)
CI 
helm upgrade --install trophic-canary ./helm/trophic-app \
  --namespace  ${{ env.PROD_NAMESPACE }} \
  --set        image.tag=${{ env.IMAGE_TAG }} \
  --set        replicaCount=1 \
  --set        ingress.annotations."nginx\.ingress\.kubernetes\.io/canary"=true \
  --set        ingress.annotations."nginx\.ingress\.kubernetes\.io/canary-weight"=20 \
  --atomic --timeout 5m
Deploys a 1-replica canary release with NGINX's canary-weight annotation set to 20 — NGINX Ingress routes 20% of production traffic to the canary pod. After a 30-second soak, the CI workflow checks canary pod health before proceeding to the full rollout.
Uninstall a Helm release
CI 
helm uninstall trophic-canary --namespace ${{ env.PROD_NAMESPACE }}
Removes the canary release and all its Kubernetes resources after the full production rollout succeeds. Keeps the cluster clean between deployments.
List installed releases
Any 
helm list --all-namespaces
Shows all Helm releases across all namespaces with their chart version, app version, and status. Quick overview of what's deployed in the cluster.
Docker
Multi-stage image build, tagging, and pushing to Azure Container Registry.
Build with BuildKit and cache
CI 
docker buildx build \
  --platform   linux/amd64 \
  --tag        ${{ secrets.ACR_REGISTRY }}/${{ secrets.ACR_REPOSITORY }}:${{ env.IMAGE_TAG }} \
  --cache-from type=registry,ref=${{ secrets.ACR_REGISTRY }}/${{ secrets.ACR_REPOSITORY }}:buildcache \
  --cache-to   type=registry,ref=${{ secrets.ACR_REGISTRY }}/${{ secrets.ACR_REPOSITORY }}:buildcache,mode=max \
  --push       .
Builds a multi-stage Docker image for linux/amd64 using BuildKit's registry cache. Layer caches are read from and written back to ACR under the :buildcache tag — keeps CI build times under 3 minutes even on cold runners.
FlagPurpose
--platform linux/amd64Force AMD64 architecture (AKS node pools are AMD64)
--cache-fromPull layer cache from a remote registry before building
--cache-to mode=maxPush all layers (not just final stage) to the cache tag
--pushPush the built image to the registry without a separate docker push
Pull and run image locally
Local 
docker run --rm -p 3000:3000 \
  -e DATABASE_URL=postgresql://... \
  trophictech.azurecr.io/mission-control:latest
Runs the production image locally for quick smoke testing before pushing. --rm deletes the container on exit. Environment variables are injected with -e flags.
curl
HTTP testing from local and inside containers.
Test external endpoint
Local 
curl -I http://app.68.220.239.81.nip.io
Fetches only the response headers (-I = HEAD request). Returns HTTP status code and server headers without downloading the body — quick way to verify the ingress is routing requests correctly after a deploy.
FlagPurpose
-ISend HEAD request — headers only, no body
-sSilent — suppress progress and error messages
-fFail silently on HTTP errors (returns exit code 22)
--max-time NMaximum time for the entire operation in seconds
--retry NRetry up to N times on transient failures
Health check with JSON grep (in-pod)
CI 
curl -sf http://localhost:3000/api/health | grep -q '"status":"ok"'
The in-pod health check used by both staging smoke tests and production health checks. Runs inside the container via kubectl exec so it tests only the Next.js API handler — no load balancer, ingress, DNS, or NSG involved. Replaced the unreliable external curl that was returning exit code 28.
Terraform
Infrastructure-as-Code for provisioning the Azure resources underpinning the platform.
Initialise working directory
Local 
terraform init \
  -backend-config="storage_account_name=trophictfstate" \
  -backend-config="container_name=tfstate" \
  -backend-config="key=prod.terraform.tfstate"
Downloads provider plugins and configures the Azure Blob Storage backend for remote state. Remote state ensures multiple team members share the same lock and state file — prevents concurrent applies from conflicting.
FlagPurpose
-backend-configInject backend configuration at init time (avoids hardcoding in .tf files)
-upgradeUpgrade provider plugins to latest allowed version
-reconfigureReconfigure backend without migrating existing state
Preview changes
Local 
terraform plan -out=tfplan -var-file=prod.tfvars
Compares desired state (HCL files) with actual Azure resource state and outputs a diff. Saving to -out=tfplan creates a plan file that terraform apply tfplan can execute exactly — no re-plan, no drift.
FlagPurpose
-outSave the plan to a file for deterministic apply
-var-fileLoad variable values from a .tfvars file
-targetLimit plan to a specific resource (use sparingly)
Apply infrastructure changes
Local 
terraform apply tfplan
Executes the saved plan against Azure. Applying a pre-built plan file skips the approval prompt and guarantees exactly what was reviewed gets applied — required for automated pipelines and audit trails.
Show current state
Local 
terraform show -json | jq '.values.root_module.resources[].address'
Dumps the full Terraform state as JSON and pipes to jq to list all tracked resource addresses. Used to audit what Terraform currently manages — handy when debugging drift or importing existing resources.
Import existing resource into state
Local 
terraform import \
  module.aks.azurerm_kubernetes_cluster.main \
  /subscriptions/<sub-id>/resourceGroups/trophic-prod-rg/providers/Microsoft.ContainerService/managedClusters/trophic-aks
Brings an existing Azure resource under Terraform management without recreating it. Used when the AKS cluster was provisioned manually first and later adopted into IaC.
